# /lore-setup

Initializes Lore and (optionally) imports the user's existing notes. The deterministic
work (scaffold, register, write entries, regenerate index maps, daily logs, dedup) is done
by the core-lib CLI. THIS skill supplies the judgment the CLI can't: which source files are
worth storing, and how to distill each into a schema-v2 entry.

## Runtime

Resolve the bundled CLI once, then call subcommands. Requires node >= 20 on PATH.

```bash
# Bundled Lore CLI: plugin install dir, plugin cache, or a dev checkout.
LORE_CLI="${CLAUDE_PLUGIN_ROOT:+$CLAUDE_PLUGIN_ROOT/dist/cli.mjs}"
[ -f "$LORE_CLI" ] || LORE_CLI="$(ls "$HOME"/.claude/plugins/cache/*/lore/dist/cli.mjs "$HOME"/.claude/plugins/*/lore/dist/cli.mjs 2>/dev/null | head -1)"
[ -f "$LORE_CLI" ] || LORE_CLI="$HOME/work/lore/dist/cli.mjs"
LORE() { node "$LORE_CLI" "$@"; }
```

All CLI output is one JSON line on stdout. Parse it; on `ok:false` or a non-zero exit, stop
and show the user the stderr.

## Step 1 — scaffold + register

```bash
LORE scaffold
LORE register "$(git rev-parse --show-toplevel 2>/dev/null || pwd)"
```

`register` prints the project slug. Hold onto it — every entry's `project` is this slug.

## Step 2 — offer bootstrap ingest

Ask the user (AskUserQuestion or prose): "Point me at directories/files where you already
keep plans and memories, and I'll import them. Or skip and start fresh."

If they skip, stop here — setup is done.

If they give paths, scan them:

```bash
LORE ingest-scan <path...>
```

This returns `{ candidates: [{ path, source_hash }] }` — markdown files not already imported
(build/vcs/_archive dirs are skipped automatically, and re-runs skip what's already in the
store by `source_hash`).

## Step 3 — for each candidate, judge then distill

Read each candidate file. Then:

**3a. Worth-storing filter (the make-or-break gate).** Skip a file if it is: transient
scratch, a duplicate of another note, pure boilerplate, or has no durable "why / what / how /
status" value. Keep: decisions, plans, feature walkthroughs, status/progress, reusable
references, dated findings. When unsure, lean skip — a noisy KB is worse than a small one.
Tell the user what you skipped and why (one line each).

**3b. Distill a kept file into a schema-v2 entry** and write it:

```bash
printf '%s' '<PutInput JSON>' | LORE put
```

`PutInput` fields (only `type`, `project`, `feature`, `title`, `body` are required):

- `type`: decision | fix | status | walkthrough | reference | plan
- `project`: the slug from Step 1
- `initiative`: parent initiative id when the note belongs to a multi-PR effort (e.g. `PROJ-110`)
- `feature`: stable kebab feature id (e.g. `checkout-flow`, `search-filters`)
- `repos_involved`: array of repo names the note touches (read or changed)
- `title`: one-line summary (becomes the index.md map line)
- `date`: ISO day the work happened (from the note's content/dates; falls back to today)
- `created_at`: full ISO timestamp (falls back to now)
- `epic` + `subtasks`: split Jira (epic id + array of subtask ids) — G7
- `prs`: array of `{ repo, pr, ticket, status, merged_date }` — G2
- `checklist`: array of `{ text, checked }` for testing/QA gates — G5
- `files`: object of `repo -> [paths]` — G6
- `status`: in-progress | shipped | abandoned | blocked (for `type: status`)
- `body`: the DISTILLED prose — compiled "why/what/how", sources traceable, not the raw dump
- `source_hash`: pass the candidate's `source_hash` verbatim so re-runs dedup correctly

Distillation rules: compress to the durable knowledge, keep Jira/PR/file references, drop
chatter. One source file may yield several entries (e.g. a plan with distinct decisions) —
or one. A long running progress doc maps to a `type: status`/`plan` entry plus, if useful,
atomic `decision`/`fix` entries for the load-bearing calls inside it.

`id` is auto-assigned (`{feature}-{NNN}`) and the feature/project/root index.md maps + the
`metadata/<date>.md` daily log are regenerated by `put` — do not write those by hand.

## Step 4 — report

Summarize: store path, project slug, N files scanned, M imported, K skipped (with reasons),
and the feature/initiative tree created. Suggest `/lore-ask` to query it.

## Notes

- Idempotent: re-running `/lore-setup --ingest` over the same paths imports nothing new.
- Never touches the user's source repos — only writes under `~/.lore` (or `$LORE_HOME`).
- Phase A is Claude-Code-only and manual-write; auto-capture + MCP write land in Phase B.
